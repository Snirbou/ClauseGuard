## 2) System Architecture View

תזרים נתונים (נכון לשלב 1):

```
Upload PDF → Validate (type check) → Extract Text (PyMuPDF)
    → Naive Segmentation (blank-line split)
    → 🆕 Mock ML Classification (rule-based, per segment)
    → 🆕 Persist to PostgreSQL (contracts + parsed_clauses)
    → Return JSON Handoff (with UUIDs, clause_type, confidence)
    → UI renders parsed_clauses (backward-compatible)
```

**גבולות ארכיטקטוריים:**
- **`frontend/`** (Next.js) — שולח `POST /api/contracts/upload` עם `multipart/form-data`. לא שונה בשלב זה. ממשיך לצרוך את `filename` ו-`clause_index` מהתשובה.
- **`backend/`** (FastAPI) — מחזיק את כל הלוגיקה: parsing, segmentation, classification, persistence, ו-JSON response construction.
- **PostgreSQL** (Docker) — מסד נתונים חדש שרץ לוקאלית בקונטיינר. הטבלאות נוצרות אוטומטית ב-startup.
- **אין ישויות `users`** בשלב זה — שמור לשלב 3.

## 4) Core Achievements (Technical)

### 4.1 הקמת שכבת Database (PostgreSQL + Async SQLAlchemy)

- **מה השתנה:** נוספו 4 קבצי תשתית חדשים: `config.py`, `database.py`, `models.py`, `docker-compose.yml`.
- **למה:** כדי לעבור מצינור Stateless (חילוץ → החזרה → שכחה) לצינור Stateful שבו הנתונים נשמרים ב-DB ומפתח 2 יכול לשלוף אותם לצורך הרצת DSPy.
- **איפה בקוד:**
  - `backend/config.py` → `Settings` (pydantic-settings, טוען `DATABASE_URL` מ-`.env`)
  - `backend/database.py` → `engine`, `async_session_factory`, `Base`, `get_db()` (FastAPI dependency)
  - `backend/models.py` → `Contract`, `ParsedClause` (SQLAlchemy ORM)
  - `docker-compose.yml` → Postgres 16 Alpine container (`clauseguard:clauseguard@localhost:5432/clauseguard`)
- **השפעה/סיכונים:**
  - הטבלאות נוצרות אוטומטית ב-startup דרך `Base.metadata.create_all` (ב-`lifespan` context manager). **אין עדיין Alembic migrations** — מספיק ל-dev, אך יידרש לפני Production.
  - `expire_on_commit=False` ב-session factory — קריטי כדי שנוכל לקרוא `row.id` אחרי `commit()` בלי lazy load.

### 4.2 Mock ML Classifier (מסווג דמה)

- **מה השתנה:** נוצר `backend/classifier.py` עם פונקציית `mock_classify(raw_text) → (clause_type, confidence)`.
- **למה:** כדי למלא את שדות ה-`clause_type` ו-`clause_type_confidence` ב-API Contract מבלי להמתין לאימון מודל Scikit-Learn אמיתי. מפתח 2 יכול להתחיל לעבוד מיד עם הנתונים ב-DB.
- **איפה בקוד:** `backend/classifier.py → mock_classify()`
- **כללי סיווג (7 + fallback):**

| מילות מפתח (דוגמא) | `clause_type` | `confidence` |
|---|---|---|
| intellectual property, work product | `ip_assignment` | 0.92 |
| payment, invoice, fee | `payment_terms` | 0.85 |
| terminat, cancel, expir | `termination` | 0.88 |
| liable, liability, indemnif | `liability` | 0.83 |
| confidential, non-disclosure | `confidentiality` | 0.90 |
| scope of work, deliverables | `scope_of_work` | 0.80 |
| governing law, jurisdiction | `governing_law` | 0.87 |
| (ללא התאמה) | `general` | 0.50 |

- **השפעה/סיכונים:**
  - המסווג פועל על בסיס `str.lower()` + `any(kw in text_lower)`. **הוא לא מסוגל לזהות שפות שאינן אנגלית** — מילות מפתח בעברית לא יזוהו. זה צפוי ומספיק לשלב זה.
  - **בעלות: מפתח 1 (Full-Stack & ML)** אחראי להחליף את הפונקציה הזו במודל spaCy + Scikit-Learn אמיתי. **מפתח 2 (DSPy) לא נוגע בקובץ הזה** — הוא רק צורך את הרשומות מ-DB.

### 4.3 שדרוג Endpoint `/api/contracts/upload`

- **מה השתנה:** ה-Endpoint עבר שדרוג משמעותי — הוסף DB session injection, לולאת סיווג, שמירה ב-DB, ומבנה JSON חדש.
- **למה:** כדי לממש את ה-Enrichment Pipeline ולהחזיר את ה-Handoff JSON המדויק שמפתח 2 דורש.
- **איפה בקוד:** `backend/main.py → upload_contract()` (L103–L209)
- **זרימה חדשה:**
  1. ולידציה ו-parsing (ללא שינוי מ-Phase 0).
  2. **סיווג:** לולאה על `segments`, הפעלת `mock_classify(cleaned)` לכל סעיף, צבירה למערך `classified`.
  3. **שמירה:** יצירת `Contract` → `db.flush()` (לקבלת UUID) → יצירת `ParsedClause` לכל סעיף → `db.commit()`.
  4. **תשובה:** בניית JSON Handoff עם `contract_id`, `parsed_clause_id`, `clause_type`, `clause_type_confidence`, **וגם** `filename` ו-`clause_index` (תאימות לאחור).
- **תיקון באג מ-Phase 0:** נוסף `except HTTPException: raise` לפני ה-`except Exception` הכללי (L203–204), כך שחריגות ולידציה לא נבלעות יותר.
- **השפעה/סיכונים:**
  - אם ה-DB לא רץ, השרת יקרוס ב-startup (ה-`lifespan` מנסה ליצור טבלאות).
  - אין עדיין timeout או rate limiting על ה-Endpoint.

## 5) API Contracts & DB Schema (Crucial for Dev1 ↔ Dev2 Sync)

### 5.1 Strict API Contract: `POST /api/contracts/upload`

**Request:**
- `Content-Type: multipart/form-data`
- field name: **`file`** (בדיוק)
- **Max file size (10MB):** כרגע **אין אכיפה בקוד** (לא השתנה מ-Phase 0).

**Response — Success (`200`)**
```json
{
  "status": "success",
  "filename": "msa.pdf",
  "contract_id": "bdab9a61-9b70-4f27-97ce-bc600d892442",
  "parsed_clauses": [
    {
      "parsed_clause_id": "fe3ba60d-e201-4a6a-ab7a-489c130d3656",
      "contract_id": "bdab9a61-9b70-4f27-97ce-bc600d892442",
      "clause_index": 1,
      "raw_text": "This Agreement starts on the Effective Date...",
      "clause_type": "general",
      "clause_type_confidence": 0.50
    }
  ]
}
```

**Response — Error (`400`)**
```json
{
  "status": "error",
  "filename": "uploaded.mp4",
  "contract_id": null,
  "parsed_clauses": [],
  "detail": "Invalid file type. PDF required."
}
```

**כללים קשיחים (חייבים להישמר):**
- `status` — תמיד `"success"` או `"error"`.
- `filename` — echo של שם הקובץ שהועלה (**נשמר מ-Phase 0 לתאימות לאחור**).
- `contract_id` — UUID של החוזה ב-DB (או `null` בשגיאה).
- `parsed_clauses` — מערך, ריק `[]` בשגיאה.
- `parsed_clauses[].parsed_clause_id` — UUID ייחודי מ-DB.
- `parsed_clauses[].contract_id` — echo של ה-UUID של החוזה.
- `parsed_clauses[].clause_index` — מספר שלם, 1-based, מונוטוני (**נשמר מ-Phase 0**).
- `parsed_clauses[].raw_text` — טקסט הסעיף.
- `parsed_clauses[].clause_type` — אחד מ: `ip_assignment`, `payment_terms`, `termination`, `liability`, `confidentiality`, `scope_of_work`, `governing_law`, `general`.
- `parsed_clauses[].clause_type_confidence` — float בטווח `[0.0, 1.0]`.

## 8) Observability & Maintenance

### איך מריצים מקומית (סדר חובה)

**1. הרמת PostgreSQL:**
```powershell
docker compose up -d
```
*(מתיקיית השורש `ClauseGuard`)*

**2. התקנת Dependencies:**
```powershell
pip install -r backend/requirements.txt
```

**3. הפעלת Backend:**
```powershell
cd backend
uvicorn main:app --reload --port 8000
```
*(ב-startup ראשון, ה-`lifespan` יוצר אוטומטית את הטבלאות ב-DB)*

**4. הפעלת Frontend:**
```powershell
cd frontend
npm install
npm run dev
```

### איפה רואים לוגים ושגיאות
- **Backend:** stdout של `uvicorn` — כולל שגיאות parsing, DB connection errors
- **Frontend:** terminal של `npm run dev` + Browser DevTools → Console / Network
- **PostgreSQL:** `docker logs clauseguard-db` (לוגים של הקונטיינר)
- **DSPy optimizer traces:** לא קיימים עדיין

### Known Failure Modes
- **DB לא רץ:** אם Docker לא פעיל, ה-`lifespan` של FastAPI ייכשל ב-startup (`connection refused`). **פתרון:** `docker compose up -d`.
- **PDF ללא טקסט:** מחזיר error envelope עם `detail: "Could not extract text from PDF."` — כרגע אין הבחנה בין PDF סרוק לבין PDF ריק.
- **קובץ לא-PDF:** נתפס ב-`_is_pdf_upload()` → error 400.
- **פער 10MB:** אין ולידציית גודל קובץ בקוד (ב-UI ובשרת). פער ידוע מ-Phase 0, **טרם טופל**.
- **Docker `version` warning:** `docker-compose.yml` מכיל `version: "3.9"` שמייצר אזהרה (`the attribute 'version' is obsolete`). אינו משפיע על פעולת הקונטיינר.
