## 2) System Architecture View

תזרים נתונים נכון לסיום הסשן (Production):

```
Upload PDF → Validate (PDF check) → Extract Text (PyMuPDF)
    → Naive Segmentation (blank-line split)
    → 🟡 Mock ML Classification (rule-based)  [STILL ACTIVE — not yet swapped]
    → Persist to PostgreSQL (contracts + parsed_clauses)
    → Return JSON Handoff (UUIDs, clause_type, confidence)
```

תזרים נתונים נכון לסיום הסשן (Sandbox — מנותק מ-Production):

```
HuggingFace LEDGAR (60K) → Label Map 100→8 → MinHash Dedup (55,873)
    → Cap "general" 1.5x (25,678) → train/test split
    → FeatureUnion: TfidfVectorizer(sublinear_tf, 1-3 grams)
                  + LegalFeatureExtractor (NER counts, deontic modals, syntactic)
    → StandardScaler(with_mean=False) on dense branch
    → CalibratedClassifierCV(LinearSVC(class_weight="balanced"), cv=3, sigmoid)
    → GridSearchCV(5-fold × 8 candidates × n_jobs=1)
    → joblib dump → backend/models/clause_classifier_v1.joblib
```

### 4.4 אימון GridSearchCV + הסבר על קריסות ושיפורים

- **מה השתנה:** הסקריפט `04_train.py` רץ במלואו (לאחר תיקון `n_jobs`), Cap על "general" של **1.5x** (=7,071 שורות, יורד מ-37,266 הראשוניים) הצליח, GridSearchCV של 5-fold × 8 candidates = 40 fits הסתיים.
- **למה:**
  - **Cap 1.5x (במקום 3x):** קטגוריית `general` היא "פח אשפה" של 92 LEDGAR labels — אילו ניתן לה גודל פי 3, היא הייתה משתלטת על המודל ופוגעת ב-Macro F1.
  - **Inner CV=3 (במקום 5):** Calibration כפול cross-validation עלולה לרוץ שעות. הקטנה ל-3 חוסכת 40% חישוב עם פגיעה זניחה בסטטיסטיקה.
- **איפה בקוד:**
  - `backend/ml_training/scripts/04_train.py` → קורא `ledgar_train_deduped.parquet`, מבצע downsample של "general" ל-1.5×, מאמן `Pipeline` מ-`build_pipeline()`, GridSearch על `clf__estimator__C ∈ {0.1, 0.5, 1.0, 5.0}` × `transformer_weights ∈ [{tfidf:1, legal:1}, {tfidf:1, legal:2}]` עם `scoring="f1_macro"`, `cv=5`, `n_jobs=1`, **Acceptance gate**: `macro-F1 ≥ 0.85` AND כל per-class F1 ≥ 0.75
  - `backend/ml_training/src/pipeline.py:115-128` → `LinearSVC(C=..., class_weight="balanced", dual="auto", max_iter=5000)` עטוף ב-`CalibratedClassifierCV(method="sigmoid", cv=3, ensemble=True, n_jobs=1)`

  | מטריקה | ערך |

### 4.5 קריסת `MemoryError` ותיקון `n_jobs`

- **מה השתנה:** הריצה הראשונה של `04_train.py` קרסה אחרי ~32/40 fits עם `joblib.externals.loky.process_executor.BrokenProcessPool` ושגיאת `MemoryError` ב-Windows multiprocessing.
- **למה:** `GridSearchCV` הריץ ב-`n_jobs=-1` (כל הליבות במקביל). ב-Windows אין `fork()` — `loky` משכפל את כל הוקטור TF-IDF (25K סעיפים × 80K ממדים) לכל ליבה דרך pickle. ה-RAM פוצץ.
- **תיקון (APPLY):** `backend/ml_training/scripts/04_train.py` → שינוי `n_jobs` של ה-`GridSearchCV` מ-`-1` ל-`1`.
- **השפעה/סיכונים:**
  - הריצה הסופית אחרי התיקון רצה **טורית**, ולקחה מספר שעות (אחד ה-folds לקח 137 דקות). **רץ עד הסוף ויציב.**
  - **לקח עתידי:** פלטפורמה Windows + sklearn + sparse vectors ענקיים → **לעולם לא להריץ עם `n_jobs=-1`**. אופציה עתידית: להעביר אימון לסביבת Linux/CI כדי לחזור למקבילות.

### 4.6 תיקוני באגים נקודתיים בסקריפטים

- **באג 1 — Regex של אחוזים ב-`preprocessing.py`:** טסט `TestNormalizeNumbers::test_substitutes_percentage` נכשל. הביטוי הקודם השתמש ב-trailing `\b` אחרי `%` שאינו תו-מילה. **תיקון:** `re.sub(r'\b\d+(?:\.\d+)?\s*%', '__PERCENTAGE__', text)`. אחרי APPLY: 19/19 טסטים ירוקים.
- **באג 2 — `trust_remote_code=True` חסר ב-`01_download_datasets.py`:** HuggingFace דורש flag מפורש למאגרים עם custom code. **תיקון:** הוספת `trust_remote_code=True` ל-`load_dataset(...)` של CUAD.
- **באג 3 — חילוץ CUAD שדות שגויים ב-`05_evaluate_cuad.py`:** הסקריפט הראשון הדפיס `No mappable CUAD examples found`. CUAD הוא במבנה SQuAD (`['id', 'title', 'context', 'question', 'answers']`). **תיקון:** איטרציה על rows, חילוץ `answers['text']` הלא-ריק, מיפוי `question` → CG8. אחרי התיקון: 1,546 דוגמאות OOD נטענו.

- **Cap על "general":** ה-PLAN המקורי הציע 3x. **שונה ל-1.5x** במהלך אישור ה-PLAN, על-בסיס המלצת ה-IDE — להפחית רעש קטגוריה אופנתית.
- **`n_jobs` ב-GridSearch:** ה-PLAN המקורי לא ציין מגבלת מקביליות. **תוקן ל-`n_jobs=1`** אחרי קריסת `MemoryError` ב-Windows.
- **OOD evaluation על CUAD:** במקור היה blocker פוטנציאלי. **הוסט להחלטה אסטרטגית:** השכבה הקלאסית עומדת ביעד על LEDGAR; OOD weakness היא בדיוק הסיבה ש-Layer 2 קיים. **לא נחזור לאמן עד שיהיה user data אמיתי.**

### Newly Discovered Constraints
- Windows + `loky` + sklearn = `n_jobs=-1` **אסור** עם sparse TF-IDF גדולים.
- HuggingFace דורש `trust_remote_code=True` ל-`theatticusproject/cuad-qa`.
- מודל `en_core_web_lg` של spaCy (~600MB) לא יורד ב-pip default timeout — נדרש `--default-timeout=1000`.
- כל ה-pinning של dependencies ב-Sandbox **down-grade** את הסביבה הגלובלית של המשתמש.
